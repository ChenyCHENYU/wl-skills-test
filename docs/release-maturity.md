# 1.0 准入评估（2026-10-11）

本轮候选保持0.33.0。1.0表示对明确公开API的稳定兼容承诺，不能仅由协议版本或通过用例数量决定。

当前判断：DI空样本与自动修复边界本轮首次收口；CLI/MCP/主库公开面、脚手架TODO与业务环境就绪边界需冻结稳定兼容承诺。

## 进入1.0的明确条件

1. 列出并冻结全部支持的CLI/MCP/库导出（如有）、参数、退出码、结构化结果、模型Schema和受管资产格式；标明私有实现。
2. 以真实已发布0.x产物验证正常update、冲突零写入、卸载保留用户内容；单包不需兄弟包，混合版本不强求五包同版。
3. 参数Schema与运行时一致；正常、违规、空/未知输入、版本漂移、路径边界、取消/输出超限均有精确回执。
4. 原CLI与结构化execute调用同一业务执行器；新规则由本包维护，Harness动态消费目录，不建立第二份规则或CLI参数表。
5. 定义业务验证范围与未验证状态。已承诺范围必须有实际证据，超出范围明确partial/unverified/TODO；不能以模型未验证长期阻断本可独立验证的工具公开面。
6. 固定上述发布验收入口和CI证据，至少把本轮新执行入口的真实发布包作为后续兼容基线；任何不兼容变更按版本契约处理。

真实宿主/模型事件未验证、Windows取消尚无本机证据，是清楚标示的环境验证边界，不独自构成永久留在0.x的理由。本包本轮继续保留0.x，先完成上述公开面与业务验证范围的稳定承诺，再单独评估1.0。
